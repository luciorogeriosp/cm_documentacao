### **Resumo**

O grupo unificou a nomenclatura de aulas e definiu fluxos operacionais para doações e design do sistema.

**Unificação da terminologia sistêmica**  
Ficou definido que o termo aula cobrirá todas as sessões presenciais e ao vivo para garantir consistência. Conteúdos adicionais serão classificados como conteúdo extra para maior clareza pedagógica.

**Análise de fluxos financeiros**  
O sistema exigirá o envio obrigatório de comprovantes financeiros para garantir a qualidade da análise de dados. O fluxo de doações de capital semente foi discutido visando evitar expectativas precipitadas.

**Planejamento de interface visual**  
A equipe avaliou opções de interface para o sistema, priorizando a funcionalidade e o engajamento das usuárias. O layout de blocos foi o modelo proposto para a estruturação das telas.

### **Decisões**

## Alinhada

* **Unificação de tipos de aula** A fusão dos módulos de aula ao vivo e aula presencial em um único tipo, denominado 'aula', é definida para simplificar a estrutura do sistema.

* **Critério de contagem para conteúdo extra** Conteúdos adicionais não contabilizam para a porcentagem de progresso ou carga horária obrigatória do programa.

* **Uso do termo conteúdo extra** A terminologia 'conteúdo extra' substitui 'aula extra' para permitir maior abrangência e flexibilidade no tipo de evento.

* **Encerramento como módulo obrigatório** O evento de encerramento é configurado como um módulo obrigatório no sistema para contabilizar na carga horária total da jornada.

* **Adoção do termo revisão** O termo 'revisão' substitui 'reprovação' para se referir ao status de ajustes necessários em entregas e atividades.

* **Confirmação em duas etapas para doações** A aprovação de doações requer uma confirmação em duas etapas para evitar erros de comunicação com a empreendedora.

* **Dados bancários formais para transações** A validação de doações em dinheiro exige o cadastro de dados bancários formais (nome, CPF, conta) para verificação de titularidade.

* **Instrução de aguarde para próximos passos** O sistema deve exibir a mensagem 'aguarde' para próximos passos, evitando a exposição prematura de datas ou prazos específicos.

* **Obrigatoriedade de anexos financeiros** O envio de comprovantes financeiros (planilha ou imagem do livro caixa) é definido como obrigatório para a validação das atividades.

* **Fluxo de assinatura de recibos definido** O processo de assinatura de recibos para doações de equipamentos foi definido para ocorrer obrigatoriamente após a confirmação do recebimento do produto pelo empreendedor.

* **Design visual da interface definido** O estilo visual da interface do sistema será uma mescla entre os designs 'Blocos' e 'Imersiva', priorizando uma estética mais colorida conforme consenso da equipe.
